# Persiapan penjualan Google Play

Project ini menghasilkan file instalasi dan signed AAB; belum menjadi aplikasi yang disetujui Google Play.

1. Dapatkan izin tertulis untuk nama/desain/merek TAG Heuer dan McLaren. Project ini independen. Tulisan disclaimer tidak menggantikan lisensi. [Kebijakan IP Google Play](https://support.google.com/googleplay/android-developer/answer/9888072).
2. Pilih akun developer dan verifikasi identitas. Daftarkan package `com.deploydulupulangnanti.tagheuermclarenwf` untuk satu listing yang melayani ponsel/tablet dan Wear OS melalui jalur faktor bentuk masing-masing.
3. Backup keystore offline. Alias `tag-heuer-watch-faces`. Gunakan Play App Signing dan ikuti pilihan upload key/app signing key di Console. Jangan menghapus atau meregenerasi key yang sudah dipakai tanpa proses rotasi resmi.
4. Jalankan CI, release workflow, validator WFF dan evaluator memori. Uji pada jam Wear OS 4 minimum serta versi baru, layar kecil/besar, perubahan zona waktu, format 12/24, ambient, warna, penggunaan baterai dan instalasi melalui track Play.
5. Lengkapi listing berbayar, kategori watch face, negara distribusi, harga dan pajak. Ketersediaan Google Play/pembayaran berbeda menurut negara; jangan menjanjikan semua negara/perangkat.
6. Buat screenshot aktual di jam, icon/feature graphic sesuai spesifikasi Console, deskripsi yang akurat, email support dan URL privacy policy publik. Preview dari source bukan screenshot pengujian perangkat.
7. Lengkapi Data safety, rating konten, deklarasi iklan (tidak ada), dan deklarasi lainnya berdasarkan APK final. Kebijakan privasi Indonesia/Inggris tersedia di `index.html`, dengan kontak seandyadryan2@gmail.com. Hosting file ini pada URL HTTPS publik dan gunakan URL tersebut dalam listing; sesuaikan kebijakan jika fitur/data aplikasi berubah.
8. Aktifkan faktor bentuk **Wear OS** melalui **Setelan lanjutan > Faktor bentuk > Tambahkan faktor bentuk**. Pada halaman jalur pengujian/production, pilih **Wear OS saja / Wear OS only** sebelum membuat rilis dan menambahkan **wear-release.aab**. Jangan mengunggah paket Wear OS ke jalur ponsel. Bila paket terlanjur masuk ke draft rilis ponsel, hapus paket itu dari draft atau buang draft yang hanya berisi paket Wear OS, lalu buat rilis pada jalur Wear OS khusus. Bila bundle sudah tersedia di library Console, tambahkan bundle yang sama dari library ke jalur yang benar; tidak perlu mengunggah ulang versionCode yang sudah diterima. Ikuti langkah opt-in/review Wear OS yang ditampilkan Console. [Panduan jalur khusus faktor bentuk](https://support.google.com/googleplay/android-developer/answer/13295490).
   Pendamping Kotlin menggunakan package dan signing key yang sama. Upload **companion-release.aab** versi 6 pada jalur ponsel/tablet dalam listing yang sama; jangan memasukkannya ke jalur Wear OS. Upload **wear-release.aab** versi 5 pada jalur Wear OS khusus. Keduanya AAB terpisah dengan versionCode unik; jangan menambahkan kode Kotlin ke AAB WFF. [Pedoman package pendamping WO-G7](https://developer.android.com/develop/adaptive-apps/quality-guidelines/wear-app-quality). Tautan companion ke Play baru berfungsi setelah listing tersedia bagi akun penguji/pengguna.
9. Selesaikan internal/closed testing serta persyaratan akun yang ditampilkan Console sebelum production. Terjemahan perlu review penutur asli dan listing perlu terjemahan terpisah.
10. Naikkan `versionCode` pada setiap upload berikutnya. Jangan mengganti `applicationId` setelah publikasi.

Tidak ada auto-publish atau kredensial Play Console di repository. GitHub Actions hanya membuat artifact untuk diunduh. Persyaratan Google dapat berubah; cek [kualitas aplikasi Wear](https://developer.android.com/docs/quality-guidelines/wear-app-quality) dan Console saat rilis.
